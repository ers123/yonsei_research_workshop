# 07. Long Thesis Section-by-Section Prompt

장문 학위논문이나 긴 원고를 한 번에 쓰게 하지 않고, 먼저 자료를 학습시킨 뒤 상세 목차와 문단 단위로 확장하는 프롬프트입니다.

아래 프롬프트는 참고 영상의 핵심 전략을 연구실 논문 작성 상황에 맞게 재작성한 것입니다. 영상 자막을 장문 그대로 옮긴 verbatim transcript가 아니라, 그대로 복사해서 쓸 수 있는 working prompt입니다.

## 1. 자료 학습만 시키기

```text
지금부터 내가 연구자료와 문헌 흐름 정리본을 순서대로 제공하겠습니다.

중요:
- 아직 제목, 목차, 초록, 본문, 요약, 평가를 생성하지 마세요.
- 지금 단계에서는 자료를 읽고 학습만 하세요.
- 답변은 길게 하지 않아도 됩니다.
- 각 자료를 읽은 뒤 "검토 완료. 아직 생성하지 않음." 정도로만 확인하세요.

학습할 관점:
1. 연구주제와 핵심 개념
2. 반복해서 등장하는 이론 또는 선행연구 흐름
3. 서로 연결되는 주장
4. 아직 근거가 약한 부분
5. 학위논문에서 다룰 수 있는 범위
6. 인용 또는 참고문헌 확인이 필요한 부분

생성 금지:
- 제목 제안 금지
- 목차 작성 금지
- 본문 작성 금지
- 새로운 문헌 지어내기 금지
- 자료에 없는 주장 추가 금지

이제 첫 번째 자료를 붙여 넣겠습니다.
```

## 2. 자료 묶음별 확인

자료가 길면 한 번에 모두 넣지 말고 1개 묶음씩 넣습니다.

```text
아래는 [자료명 또는 문헌 흐름 보고서 이름]입니다.

이 자료를 학습만 하세요.
아직 답을 만들지 말고, 다음 형식으로만 짧게 응답하세요.

응답 형식:
- 검토 상태:
- 이 자료에서 중심이 되는 개념 3개:
- 다음 자료를 기다리는 중:

[자료 붙여넣기]
```

## 3. 제목 또는 주제 후보 2-3개 요청

모든 자료를 넣은 뒤에만 실행합니다.

```text
지금까지 제공한 자료만 바탕으로 학위논문 또는 장문 원고의 주제/제목 후보를 2-3개 제안해 주세요.

규칙:
- 자료에 없는 연구대상, 데이터, 방법을 새로 만들지 마세요.
- 각 후보는 실제로 쓸 수 있는 범위여야 합니다.
- 후보마다 장점, 위험, 필요한 추가 확인 자료를 적어 주세요.

출력:
| 후보 | 잠정 제목 | 핵심 질문 | 강점 | 위험 | 추가 확인 |
|---|---|---|---|---|---|

마지막에는 가장 현실적인 후보 1개를 추천하되, 추천 이유를 자료 기반으로 설명하세요.
```

## 4. 5장 체계의 상세 목차 요청

사람이 제목 또는 방향을 선택한 뒤에 실행합니다.

```text
아래 방향으로 학위논문형 상세 목차를 작성해 주세요.

선택한 방향:
[선택한 제목 또는 연구질문]

요구사항:
- 5장 체계로 작성하세요.
- 각 장은 절, 항, 문단 단위까지 세분화하세요.
- 문단 단위 항목은 실제 본문에서 1-2개 문단으로 쓸 수 있을 정도로 작게 나누세요.
- 각 항목마다 사용할 자료 또는 문헌 흐름을 표시하세요.
- 자료가 부족한 항목은 "자료 보강 필요"라고 표시하세요.
- 아직 본문은 쓰지 마세요.

출력:
1장 서론
  1.1 ...
    1.1.1 문단 단위 목표:
    사용할 자료:
    쓰면 안 되는 주장:

2장 이론적 배경
...

마지막에:
1. 바로 쓸 수 있는 항목
2. 자료 보강이 필요한 항목
3. 사람이 먼저 결정해야 할 항목
을 분리해 주세요.
```

## 5. 목차를 문단 작성 단위로 바꾸기

상세 목차가 너무 heading처럼 보이면 이 프롬프트로 문단 단위 작업표로 변환합니다.

```text
위 상세 목차를 "본문 작성 작업표"로 바꿔 주세요.

중요:
- 목차의 하위 항목을 전부 실제 heading으로 쓰지 않아도 됩니다.
- 하위 항목 중 상당수는 본문 안의 문단 단위로 처리합니다.
- 각 문단 단위는 하나의 주장 또는 하나의 연결 기능만 맡아야 합니다.

출력 표:
| Unit ID | 위치 | 문단 목표 | 사용할 자료 | citation 필요 | 금지 주장 | 예상 길이 |
|---|---|---|---|---|---|---|

예상 길이는 다음 중 하나로 표시하세요.
- short: 4-6문장
- medium: 7-10문장
- long: 2개 문단
```

## 6. 한 unit씩만 작성

가장 중요한 실행 프롬프트입니다. 한 번에 한 장 또는 한 절을 쓰게 하지 않습니다.

```text
아래 Unit ID 하나만 작성해 주세요.

작성할 Unit ID:
[예: 1.1.1]

이 unit의 목표:
[작업표의 문단 목표]

사용 가능한 자료:
[자료명 또는 발췌 요약]

규칙:
- 이 unit만 작성하세요.
- 다음 unit으로 넘어가지 마세요.
- 자료에 없는 주장, 수치, 인용문, 참고문헌을 만들지 마세요.
- citation이 필요한 문장에는 [citation needed: 자료명]처럼 표시하세요.
- 학위논문 문체로 쓰되, 과장된 일반화는 피하세요.
- 이전 unit과 자연스럽게 이어질 수 있도록 첫 문장과 마지막 문장을 조정하세요.

출력:
## Draft Unit
[본문]

## Evidence Used
- 사용한 자료:
- 자료에서 직접 뒷받침되는 주장:
- 약한 주장 또는 확인 필요:

## Reference/Citation Status
- confirmed:
- needs verification:
- do not cite yet:
```

## 7. 길이를 늘려야 할 때

분량이 부족할 때는 새 내용을 invent하지 말고 unit을 더 잘게 쪼개거나 한 문단의 논리 기능을 풍부하게 합니다.

```text
아래 unit의 길이를 늘리고 싶습니다.

금지:
- 새로운 문헌을 만들지 마세요.
- 자료에 없는 연구결과를 추가하지 마세요.
- 같은 말을 반복하지 마세요.

가능한 방식:
1. 개념 정의를 더 분명히 하기
2. 선행연구 흐름의 연결문 강화하기
3. 연구문제와의 관련성을 설명하기
4. 한계를 caveat로 명시하기
5. 다음 unit으로 넘어가는 transition 추가하기

먼저 이 unit을 더 세분화할 수 있는지 판단하고, 가능하면 2-3개의 sub-unit으로 나눠 주세요.
그 다음 내가 선택한 sub-unit만 다시 작성하세요.

대상 unit:
[본문 또는 unit 설명]
```

## 8. 각 unit 후 검토

```text
방금 작성한 unit을 검토해 주세요.

검토 기준:
1. 자료에 없는 claim이 있는가?
2. citation needed가 누락된 문장이 있는가?
3. 이전 unit과 논리적으로 이어지는가?
4. 다음 unit으로 넘어가기 전에 사람이 확인해야 할 점은 무엇인가?
5. 너무 넓은 일반화나 publication-ready처럼 보이는 표현이 있는가?

출력:
| 문장 또는 부분 | 문제 | 수정 제안 | 상태 |
|---|---|---|---|

마지막에 다음 단계로 넘어가도 되는지 `go / revise / stop` 중 하나로 표시하세요.
```
