# 01. 전체 운영지도

## 핵심 관점

AI를 논문 저자로 두지 않습니다. 연구자가 director가 되고, AI는 역할별 연구보조원처럼 씁니다.

나쁜 시작:

```text
이 자료로 논문 써줘.
```

좋은 시작:

```text
이 프로젝트의 연구 질문, 사용 가능한 자료, 금지해야 할 주장, 근거가 필요한 주장, 인간이 승인해야 할 결정을 먼저 정리해줘. 아직 초안은 쓰지 마.
```

## 왜 이 방식이 필요한가

AI가 글을 빨리 만들어 줄수록, 심사와 지도는 다음 질문으로 이동합니다.

- 왜 이 연구문제를 선택했는가?
- 왜 이 방법을 썼는가?
- 어떤 AI 도구를 어디까지 사용했는가?
- 어떤 claim이 어떤 source에 묶여 있는가?
- hallucination, citation error, logic gap은 어떻게 확인했는가?
- quote, 통계, 개인정보, 외부 배포는 누가 승인했는가?

따라서 워크숍의 목표는 "AI로 빨리 쓰기"가 아니라 "검토 가능한 연구-writing 운영체계 만들기"입니다.

## 다섯 가지 접근의 관계

```text
공통 원칙
  -> 자료를 정리한다
  -> claim과 evidence를 묶는다
  -> draft와 review를 분리한다
  -> AI-use log를 남긴다
  -> human-only gate에서 멈춘다

접근 1: structured first-draft package
접근 2: Codex thread 연구실
접근 3: 장문 논문 workflow
접근 4: local/hybrid model 운용
접근 5: Claude Code / Antigravity harness 확장
```

## 접근별 선택 기준

| 학생 상황 | 추천 접근 |
|---|---|
| 논문 PDF와 메모는 있는데 초안 구조가 안 잡힌다 | structured first-draft package |
| 연구실에서 같은 양식으로 초안 검토를 반복하고 싶다 | structured first-draft package |
| 한 채팅창이 너무 길어지고 일이 섞인다 | Codex thread 연구실 |
| 문헌, 데이터, 시각화, 검증을 서로 다른 관점에서 보고 싶다 | Codex thread 연구실 |
| 학위논문처럼 긴 분량을 구성해야 한다 | 장문 논문 workflow |
| "서론 써줘"로는 문단이 얇고 산만해진다 | 장문 논문 workflow |
| raw data나 인터뷰 원문을 외부로 보내기 어렵다 | local/hybrid model 운용 |
| cloud model이 특정 표현이나 민감 주제에서 막힌다 | local/hybrid model 운용, 단 human/legal/ethics gate 유지 |
| 연구실 구성원이 Claude Code를 주로 쓴다 | Claude Code / Antigravity harness 확장 |
| Antigravity에서 같은 supervisor-worker 운영을 해보고 싶다 | Claude Code / Antigravity harness 확장, 단 직접 호환이 아니라 rule/workflow로 변환 |

## 설명 순서

발표에서는 도구 이름보다 운영 논리를 먼저 설명합니다.

1. AI 시대 논문 심사는 process evidence를 본다.
2. 모든 접근법은 `source -> claim -> draft -> critique -> revision -> signoff`를 공유한다.
3. structured package는 가장 재현 가능한 기본형이다.
4. Codex thread 연구실은 역할 분담과 병렬 운영을 보여준다.
5. 장문 논문 workflow는 긴 글을 문단 단위로 통제하는 방법이다.
6. local/hybrid 운용은 민감자료와 비용/정책 제약을 다루는 선택지다.
7. Claude Code/Antigravity 확장은 같은 운영 논리를 다른 agentic 도구로 옮기는 방법이다.

## 공통 파일 계약

어떤 도구를 쓰든 아래 파일은 남기는 것이 좋습니다.

| 파일 | 역할 |
|---|---|
| `task-brief.md` | 연구 질문, 대상 독자, 산출물, 언어, 범위 |
| `do-not-claim.md` | 아직 말하면 안 되는 주장 |
| `materials-inventory.md` | 어떤 자료가 있는지와 민감도 |
| `evidence-bindings.md` | claim과 source 연결 |
| `source-verification.md` | 통과/보류/차단 claim |
| `ai-use-log.md` | AI 사용 단계와 검증 방식 |
| `review-report.md` | overclaim, citation gap, privacy risk |
| `human-decisions.md` | 사람이 승인해야 할 항목 |

## 7일 실행 계획

| Day | 할 일 | 산출물 |

| 1 | 연구 질문과 자료 범위 정하기 | `task-brief.md` |

## 발표자가 강조할 문장

```text
AI를 잘 쓰는 학생은 프롬프트를 멋지게 쓰는 학생이 아니라, 어떤 자료를 어떤 주장에 연결할 수 있는지 설명하고, AI가 만든 결과를 어디서 멈춰야 하는지 아는 학생입니다.
```
