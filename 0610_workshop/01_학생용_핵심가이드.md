# 학생용 핵심가이드

이 문서는 발표자 노트가 아니라, 학생이 자신의 논문 프로젝트에 바로 적용하기 위한 가이드입니다.

## 1. 시작점

AI를 논문 저자로 두지 않습니다. 여러분이 director이고, AI는 자료정리, 구조화, 비평, 초안 작성, 검증을 돕는 연구보조원입니다.

나쁜 시작:

```text
이 자료로 논문 써줘.
```

좋은 시작:

```text
이 working folder를 먼저 검토하고, 어떤 자료가 있고 어떤 주장은 가능한지, 어떤 주장은 아직 하면 안 되는지, 어떤 산출물을 만들어야 하는지 정리해 주세요. 아직 원고는 쓰지 마세요.
```

## 2. 준비물

최소한 아래 자료가 있으면 논문 초안 패키지를 만들 수 있습니다.

| 준비물 | 설명 |
|---|---|
| RQ 또는 tentative RQ | 아직 완벽하지 않아도 방향은 있어야 합니다 |
| 핵심 논문 5-10개 | PDF, DOI, Zotero 목록, 읽은 메모 |
| 연구자 메모 | 회의록, 발표자료, 아이디어 노트 |
| findings | 데이터나 관찰에서 말할 수 있는 것 |
| benchmark paper | 구조나 문체를 참고할 논문 |
| do-not-claim | 아직 말하면 안 되는 주장 |
| 출력 언어 | 한국어, 영어, 또는 둘 다 |

## 3. 기본 폴더

복잡한 시스템 없이도 아래처럼 폴더를 만들면 충분합니다.

```text
my-paper/
  context/
    task-brief.md
    do-not-claim.md
    ai-use-log.md
  sources/
    papers/
    benchmark-papers/
  notes/
    reading-notes.md
    meeting-notes.md
  data/
    sanitized-summary.md
    analysis-tables/
  draft/
    outline.md
    first-draft.md
    review.md
    revised-draft.md
```

민감자료는 `raw-private/` 같은 별도 폴더에 두고, 외부 LLM에는 바로 올리지 않습니다.

## 4. AI에게 처음 시킬 일

처음부터 초안을 쓰게 하지 않습니다. 먼저 작업 형태를 잡습니다.

```text
이 working folder를 검토하고 다음을 정리해 주세요.

1. 이 프로젝트의 연구 질문과 잠정 논지
2. 사용 가능한 자료 목록
3. 자료별로 말할 수 있는 주장
4. 아직 하면 안 되는 주장
5. 누락된 자료
6. 먼저 만들어야 할 파일
7. 인간이 결정해야 할 사항
8. AI-use log에 남겨야 할 단계

아직 원고는 쓰지 마세요.
```

## 5. 핵심 산출물

초안 하나만 있으면 부족합니다. 최소한 아래 파일이 같이 있어야 지도교수나 동료가 검토할 수 있습니다.

| 파일 | 목적 |
|---|---|
| `task-brief.md` | RQ, 독자, 언어, 원고 종류, 금지 주장 |
| `materials-inventory.md` | 어떤 자료가 있고 어디까지 쓸 수 있는지 |
| `findings-summary.md` | 원고에 들어갈 수 있는 잠정 findings |
| `evidence-bindings.md` | claim과 source 연결 |
| `do-not-claim.md` | 아직 주장하면 안 되는 것 |
| `draft-risk-report.md` | privacy, 통계, quote, 번역, overclaim 위험 |
| `first-draft.md` | 검토용 초안 |
| `review.md` | 별도 비평 |
| `revised-draft.md` | 비평 반영본 |
| `ai-use-log.md` | AI를 어디에 썼고 어떻게 확인했는지 |

## 6. 유료 LLM 하나로 가능한 기본 workflow

ChatGPT, Claude, Gemini 중 하나만 있어도 아래 흐름은 가능합니다.

```text
1. 자료 폴더 정리
2. task shape prompt 실행
3. materials inventory 작성
4. do-not-claim 작성
5. evidence binding 작성
6. outline 작성
7. section architecture 작성
8. first draft 작성
9. 다른 세션 또는 같은 모델의 다른 역할로 critique
10. rewrite
11. AI-use log와 human decision 정리
```

중요한 점은 draft와 critique를 분리하는 것입니다. 같은 대화에서 계속 "좋게 고쳐줘"만 반복하면 AI가 자기 초안을 스스로 정당화하기 쉽습니다.

## 7. 심사에서 받을 수 있는 질문

AI 시대에는 문장이 매끈한지만 보지 않을 수 있습니다. 다음 질문에 답할 준비가 필요합니다.

- 왜 이 RQ인가?
- 왜 이 방법인가?
- 어떤 자료가 어떤 주장에 연결되는가?
- 어떤 AI 도구를 어디에 썼는가?
- AI가 만든 요약과 문장을 어떻게 검증했는가?
- 어떤 통계, quote, 윤리, 외부 배포 판단이 아직 사람의 결정인가?

## 8. 오늘의 실습 목표

워크숍 이후 바로 완성 논문을 만들 필요는 없습니다. 7일 안에 아래 5개만 만들어도 충분합니다.

1. `task-brief.md`
2. `do-not-claim.md`
3. `materials-inventory.md`
4. `evidence-bindings.md`
5. `one-section-draft.md`

그 다음 별도 critique pass를 돌리고, 지도교수나 동료에게 "완성본"이 아니라 "검토 가능한 초안 패키지"로 보여주면 됩니다.
